# Stratum: плагин курса для Claude Code

Stratum (тренажёр по Claude Code) — учебный курс, в котором вы работаете в самом Claude Code. Этот репозиторий — открытая часть курса: плагин `course` для Claude Code. Он проверяет, что установка работает, создаёт учебную папку, привязывает ваш компьютер к сайту курса, берёт с сайта задание текущего шага, проверяет вашу работу на вашем компьютере и отправляет на сайт отметку «шаг пройден» (только итог, без файлов).

Заданий, текстов модулей, правил проверки шагов и справочника здесь нет. Их отдаёт сайт курса, и только тому, кто привязал к нему компьютер. Адрес сайта даёт организатор курса; в этом репозитории его нет.

Плагин исполняет скрипты на вашем компьютере, поэтому ниже подробно сказано, что он получает с сайта, что пишет на диск и куда. Версия 0.3.0.

## Что нужно

- Claude Code, в который вы вошли платной учётной записью Claude. Какие тарифы включают Claude Code, смотрите на сайте Claude.
- Claude Code версии 2.1.287 или новее. Версию проверяет команда `/course:start`.
- Windows 11 (хватает PowerShell, который в системе уже есть) или Mac. Git, Node.js и Python не нужны.

## Установка: две команды

Откройте Claude Code и введите по очереди:

```text
/plugin marketplace add https://raw.githubusercontent.com/sollid/stratum-course/main/.claude-plugin/marketplace.json
/plugin install course@stratum-course
```

То же из обычного терминала:

```text
claude plugin marketplace add https://raw.githubusercontent.com/sollid/stratum-course/main/.claude-plugin/marketplace.json
claude plugin install course@stratum-course
```

После установки перезапустите Claude Code (закройте окно и запустите `claude` заново), чтобы команды плагина появились в списке.

## Адрес сайта курса

Плагин не знает адрес сайта заранее: вы получаете его от организатора курса (адрес вида `https://…`). Его нужно один раз сообщить Claude Code. Откройте файл `~/.claude/settings.json` (на Windows `%USERPROFILE%\.claude\settings.json`) и добавьте в него блок `env`, подставив адрес организатора; если в файле уже есть блок `env`, добавьте в него одну строку:

```json
{
  "env": { "COURSE_SITE_URL": "<адрес от организатора курса>" }
}
```

Затем перезапустите Claude Code. Плагин принимает только адреса `https://…` (для проверки на своём компьютере допускается `http://localhost`). Если адрес вписан неверно, `/course:connect` скажет об этом и ничего не отправит. Токен привязан к тому адресу, с которым вы привязались: если позже в настройках окажется другой адрес, плагин ничего не отправит и объяснит, что делать.

## Команды

1. `/course:start [папка]` — проверяет версию Claude Code, оболочку, встроенную программу проверки и (на Mac и Linux) то, что программа `awk` считает длину строки в байтах: без этого проверка шагов не заработает, и плагин скажет об этом прямо; если всё в порядке, создаёт учебную папку (без аргумента — `claude-course` в домашней папке; относительный путь тоже считается от домашней) и запоминает её путь. Папка получает метку, по которой плагин потом узнаёт её. Папку, в которой уже лежат чужие файлы, плагин учебной не делает.
2. `/course:connect` — привязывает этот компьютер к вашему профилю на сайте курса. Плагин показывает страницу и короткий код вида `ABCD-2345`; вы открываете страницу, входите на сайт, вводите код и подтверждаете. Вводите только свой код, чужой код вводить нельзя, даже если просят.
3. `/course:next` — работает только в учебной папке (в чужую плагин ничего не кладёт). Берёт с сайта задание вашего текущего шага и показывает его; когда работа готова, проверяет её на вашем компьютере, отправляет на сайт итог и, если шаг принят, сразу показывает следующий. Шаг, который сайт отдал первый раз, только показывается: это не попытка, на сайт ничего не уходит.
4. `/course:task` — ещё раз показывает текущее задание без проверки.

Если в итоге проверки сказано «спорно», шаг уходит на просмотр куратору, а следующий шаг открыт. При следующих запусках `/course:next` плагин тихо перепроверяет такие шаги и, если работа теперь принята, отправляет итог и пишет одну строку.

Пока компьютер не привязан, сайт недоступен, выключен или в режиме показа, команды прямо говорят об этом и подсказывают, что сделать; ничего не ломается.

## Удаление

Одна команда убирает каталог, плагин и данные плагина, в том числе токен привязки:

```text
/plugin marketplace remove stratum-course
```

То же из обычного терминала: `claude plugin marketplace remove stratum-course`. Только плагин, без каталога, убирает `/plugin uninstall course@stratum-course`.

Удаление плагина стирает токен на вашем компьютере, но не отзывает устройство на сайте. Устройство отзывается на сайте курса, в разделе «Мои устройства», кнопкой «Отозвать». Администратор курса может отозвать все устройства человека сразу.

## Что плагин отправляет на сайт

Только при привязке, при запросе задания и при отметке шага, и только на адрес сайта, с которым вы привязались:

- при привязке: систему (Windows, Mac или Linux), версию плагина и подпись устройства (по ней вы узнаёте свой компьютер на странице привязки). Подпись — имя компьютера без имени входа в систему, без путей, не длиннее 40 знаков. Если в имени компьютера есть ваше имя или фамилия, они попадут в подпись. Свою подпись можно задать самому: добавьте в блок `env` из раздела «Адрес сайта курса» строку `"COURSE_DEVICE_LABEL": "Рабочий ноутбук"`;
- при запросе задания: систему, версию плагина и уровень правил, которые понимает программа проверки (число). Какой шаг ваш текущий, решает сайт по токену;
- при отметке шага: модуль и шаг, пройден шаг или нет, короткий код причины (из списка кодов шага, который задаёт сайт курса, или из общего списка движка), версию плагина и версию правил проверки, систему.

Время и учётную запись сайт определяет сам: по запросу и по токену устройства. За один запуск `/course:next` уходит не больше трёх запросов (задание, отметка, следующее задание); перенаправления плагин не выполняет, токен уходит только в заголовке запроса и только на адрес, записанный вместе с ним.

## Что плагин получает с сайта и что пишет на диск

Сайт отвечает на запрос задания текстовым пакетом (формат `stratum-task 1`, описан в `RULES.md`). Это данные, а не программа: плагин ничего из пакета не исполняет. В пакете: заголовок шага, текст задания, файл правил проверки, список кодов причин и до восьми стартовых файлов. Плагин читает не больше 262144 байт ответа. Пакет, который не прошёл проверку формата, не записывается никуда, а человеку плагин говорит об этом прямо. Если шагу нужен плагин новее установленного, плагин так и скажет и ничего не запишет.

Что плагин пишет на диск и куда:

- в папку данных плагина (рядом с файлом токена, права как у него, доступ только у вашей учётной записи): `course-state.txt` (путь учебной папки, шаги, чьё задание уже показывалось, и шаги, ждущие куратора) и папка `steps/<модуль>-<шаг>/` с заданием, правилами и кодами причин шага. Правила нужны, чтобы проверять работу и тихо перепроверять спорные шаги;
- в учебную папку: метку `.stratum-course` и краткий `README.md` (при создании папки) и стартовые файлы шага, которых там ещё нет;
- больше никуда. Главный файл шага (его вы пишете сами, вместе с Claude) плагин никогда не создаёт и не меняет. Файл человека, уже лежащий по пути стартового файла, не перезаписывается. Содержимое стартовых файлов плагин в разговор не печатает.

Стартовый файл плагин кладёт только своим скриптом, не через инструменты Claude, только вместе с показом задания (перед проверкой работы ничего не восстанавливается: человек мог убрать файл нарочно; повторно положить недостающие файлы можно командой `/course:task`) и только после проверок, одинаковых с проверками сайта. Плагин сайту не доверяет: подмена ответа или ошибка сайта не должны уложить в вашу папку лишнее. Проверки пути стартового файла (не прошёл любую — файл не пишется, шаг не показывается, человеку сказано прямо):

1. путь состоит из 1–4 частей через `/`, каждая — буквы и цифры латиницы, `.`, `_`, `-`; ни одна часть не начинается с точки (поэтому нет `..` и скрытых файлов и папок вроде `.claude/`), не кончается точкой и не называется как устройство Windows (`con`, `nul`, `com1` и подобное);
2. нет абсолютных путей, диска, обратной косой черты, пробелов и других знаков;
3. расширение только `.md` или `.txt` (в шаге с версией правил 3 и выше ещё `.csv`); расширение пишется строчными буквами (`.MD` — отказ); имя файла (без учёта регистра, в любой папке) не `CLAUDE.md`, не `CLAUDE.local.md` и не `AGENTS.md` (Claude Code читает их как инструкции); это не главный файл шага и не повтор другого стартового файла (без учёта регистра);
4. путь не длиннее 120 знаков, файл не больше 16 КБ, файлов в шаге не больше восьми, в тексте нет нулевых байтов и возвратов каретки, текст в кодировке UTF-8; значения в заголовке пакета, текст задания и стартовые файлы без управляющих знаков (кроме перевода строки и табуляции; в том числе C1, разделителей строк и абзацев, знаков нулевой ширины и направления текста, знаков-тегов), иначе пакет отвергается целиком; путь стартового файла не бывает папкой другого стартового файла;
5. перед записью каждая папка на пути должна быть настоящей папкой внутри учебной, а не ссылкой (ссылка, в том числе соединение папок в Windows, — отказ); недостающие папки создаются и проверяются ещё раз; файл создаётся без перезаписи и никогда не пишется «через» ссылку.

Если положить файл не удалось, плагин говорит это прямо, называет путь файла и задание не показывает и не проверяет.

## Чего плагин не отправляет

- содержимое ваших файлов и их имена;
- пути на вашем компьютере и имя пользователя;
- текст вашего разговора с Claude;
- файлы входа в Claude и ключи: плагин их не читает.

Проверка вашей работы идёт на вашем компьютере. На сайт уходит только итог: вердикт и код причины. Правила проверки могут называть только простой файл внутри вашей учебной папки (без `..`, абсолютных путей, ссылок и соединений папок на пути, размером не больше 1 МиБ; для правил версии 3 и выше — не больше 256 КиБ); любое другое имя программа проверки отклоняет.

## Где лежит токен привязки и как его отозвать

Токен лежит в файле `device-token.txt` в папке данных плагина: `~/.claude/plugins/data/` (на Windows `%USERPROFILE%\.claude\plugins\data\`), внутри — папка этого плагина. Доступ к файлу — только у вашей учётной записи. Токен действует ограниченное время. Он нужен для двух вещей: получать с сайта задание вашего текущего шага и отправлять отметки шагов курса от вашего имени. Через него нельзя войти на сайт, читать чужие данные или менять что-то, кроме ваших отметок.

Отозвать токен: на сайте курса, в разделе «Мои устройства», кнопка «Отозвать». После отзыва следующий запрос задания или отметки получит отказ, плагин сотрёт файл токена на вашем компьютере и сам предложит привязаться заново (`/course:connect`). Файл токена можно прочитать, но не нужно пересылать его никому, в том числе в чат с Claude и в сообщения поддержке. Если токен показали кому-то по ошибке — сразу отзовите устройство.

## Для администратора компании

Плагин состоит только из читаемого текста: навыки (`SKILL.md`) и скрипты PowerShell и sh. Исполняемых файлов, хуков, серверов MCP и фоновых процессов в нём нет. Скрипты исполняются на компьютере ученика: они читают файл токена, ходят на один адрес сайта и пишут файлы только в папку данных плагина и в учебную папку (`/course:start` создаёт и недостающие папки на пути к ней; см. «Что плагин получает с сайта и что пишет на диск»). Пакет задания с сайта — данные: из него ничего не запускается.

Что понадобится разрешить:

- установку каталога и плагина. Каталог `stratum-course` читается с `raw.githubusercontent.com`; архив плагина скачивается с `github.com` с перенаправлением на хранилище файлов релизов GitHub. Разрешить нужно три хоста: `github.com`, `raw.githubusercontent.com` и хост хранилища файлов релизов (сейчас GitHub отдаёт их с `release-assets.githubusercontent.com`, раньше — с `objects.githubusercontent.com`; точное имя зависит от GitHub и уточняется при проверке установки). Все адреса — `https`;
- адрес сайта курса для привязки (его даёт организатор курса): плагин обращается только к нему и только по `https`;
- выполнение строк `!`команда`` в навыках (параметр `disableSkillShellExecution` не должен быть включён): на них построены все команды;
- на Windows: запуск `powershell.exe -ExecutionPolicy Bypass -File ...` (если политику запуска сценариев задаёт групповая политика, обход не сработает, и команда оборвётся с ошибкой PowerShell); на Mac и Linux: `sh`, `curl`, `awk`, `sed` и одна из программ `shasum`, `sha256sum`, `openssl` (для правила «файл не изменён»: плагин считает ею контрольную сумму файла из учебной папки и сверяет с суммой в правиле, файл никуда не уходит);
- способ раздачи: через настройки организации на claude.ai плагин не раздаётся (в нём есть папка `bin/`); ставьте каталог через `extraKnownMarketplaces` в управляемых настройках Claude Code.

Токен привязки лежит в папке данных плагина и защищён правами файла; при отзыве устройства или закрытии доступа на сайте он перестаёт действовать сразу.

## Что в репозитории

```text
.claude-plugin/marketplace.json   каталог: адрес архива плагина и его sha256
plugin/                           сам плагин (его же упаковывает архив)
  .claude-plugin/plugin.json      манифест
  skills/                         команды /course:start, /course:connect, /course:next, /course:task
  bin/course-run                  вход для команд (sh и cmd)
  scripts/                        скрипты PowerShell и sh: проверка, привязка, учебная папка, задание и отметка шага, тексты сообщений
  selfcheck/selfcheck.json        служебное правило самопроверки установки
RULES.md                          формат правил проверки и формат пакета задания
tests/                            тесты движка против имитации сайта
tools/pack.mjs                    сборка архива и каталога
```

Проверка репозитория (нужен Node.js 20 или новее; Windows с PowerShell 5.1 и Git Bash, либо Mac или Linux):

```text
npm ci
npm test
```

Архив собирается повторяемо: `npm run pack:check` пересобирает его и сверяет `sha256` с каталогом.
