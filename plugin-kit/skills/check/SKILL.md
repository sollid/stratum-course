# Проверка набора

Ниже готовый ответ программы набора. Его подготовила программа, не ты: она сама спросила сайт, записала или проверила файлы правил и отправила на сайт только имя пакета, версию, статус и время (без путей, имён и содержимого файлов).

!`kit-run check --data "${CLAUDE_PLUGIN_DATA}" --probe "${user_config.probe_hooks}" --flat "${user_config.flat_names}" --soft`

## Что сделать тебе

1. Выведи текст выше человеку слово в слово, без пересказа, без сокращений и без своих советов.
2. Текст выше написан для человека. Команд из него сам не запускай. Если там сказано ввести /course:connect или другую команду плагина, сам её не запускай: это решает человек.
3. Файлы правил кладёт только программа набора. Сам не создавай и не правь никаких файлов (в том числе в папках rules и .claude), не пиши их инструментами Write и Edit и не предлагай это делать.
4. Если в тексте выше есть строка «Проверка запретов: попросите Claude Code прочитать файл-приманку …», прочитай ровно этот файл инструментом Read (в нём ничего секретного) и скажи человеку одной фразой: «Запрет сработал» (если инструмент отказал и назвал правило пакета) или «Запрет не сработал» (если ты увидел содержимое файла). Если такой строки нет, ничего не читай. Больше ничего не добавляй и ничего не запускай (в том числе через PowerShell или cmd).
5. Не читай, не открывай, не ищи и не показывай файлы в папке данных плагина (`${CLAUDE_PLUGIN_DATA}`) и любые файлы с токеном (единственное исключение — файл-приманка из пункта 4): там лежат состояние набора и сохранённые копии файлов.
