# Формат правил проверки

Программа проверки (`plugin/scripts/check.ps1` для Windows и `check.sh` для Mac) читает файл правил и проверяет один файл в учебной папке. Правила — только данные: ничего из них не исполняется, не подставляется в команды и не становится регулярным выражением. Текст и названия сравниваются как буквальные строки.

## Файл правил

```json
{
  "version": 3,
  "engine": 3,
  "step": "example",
  "file": "notes/report.md",
  "skipped": "Пропущено: файла нет.",
  "rules": [
    {"id": "file-exists", "type": "file_exists", "on_fail": "failed", "ok": "Файл на месте.", "fail": "Файла нет."},
    {"id": "enough", "type": "min_items", "list": "Порядок", "min": 3, "on_fail": "almost", "ok": "Пунктов: {n}.", "fail": "Пунктов {n}, нужно не меньше {min}."}
  ]
}
```

Требования к записи (их читает `check.sh` без внешних программ, поэтому они жёсткие):

- каждое правило занимает одну строку, двоеточие стоит сразу после ключа (`"id": "x"`);
- в значениях нет двойных кавычек и обратной косой черты;
- `file` и `path` — простой относительный путь внутри учебной папки: без `..`, абсолютных путей, диска, `~`, символов `\ : * ? " < > | $` и обратной кавычки, без ссылок на пути; файл не больше 1 МиБ;
- `id` — `^[A-Za-z0-9_-]{1,40}$`; `on_fail` — `almost`, `disputed` или `failed`; любое нарушение — код выхода 2 и ни одной строки вывода.

Вывод: первая строка `verdict: accepted|almost|disputed|failed`, затем по строке на правило: `id: ok|<on_fail>|skipped - сообщение`. Вердикт — самый строгий из невыполненных правил (`failed` строже `disputed`, `disputed` строже `almost`). Если главного файла нет, все правила, кроме `file_exists` и `file_absent`, пропускаются.

В сообщениях `ok` и `fail` подставляются `{n}`, `{min}`, `{max}`, `{missing}` — у тех типов, которым они положены (см. таблицу); у остальных они становятся пустыми.

### Версия правил и «правила новее плагина»

Уровень движка: 1 — плагин 0.1.0, 2 — плагин 0.2.0 (типы и поля до раздела «Правила версии 3»), 3 — плагин 0.3.0 (правила версии 3, см. ниже). Необязательное поле файла правил `"engine": N` называет уровень, который нужен правилам. Если он больше, чем умеет установленная программа проверки, или если в правиле стоит неизвестный тип, программа завершается с кодом 2 и пишет в сообщение об ошибке `rules newer than this plugin: update the plugin`. Команда отправки отметки (`step-report`) в этом случае не отправляет ничего и говорит ученику: «Проверка не выполнена: правила этого шага новее установленного плагина… обновите плагин командой /plugin marketplace update … и введите /course:next снова» (код выхода 15).

Поле `version` — другое: это версия правил шага, она уходит на сайт вместе с отметкой.

## Типы правил

| Тип | Поля | Выполнено, если | `{…}` | Код причины по умолчанию |
|---|---|---|---|---|
| `file_exists` | `path` (необязательно) | главный файл есть; с `path` — есть обычный файл по этому пути | — | нет |
| `file_absent` | `path` (необязательно) | по пути `path` (по умолчанию главный файл) нет ни файла, ни папки | — | `file_present` |
| `has_heading` | `heading`, `scope` (необязательно) | в файле есть раздел с таким названием: заголовок любого уровня или метка | — | нет |
| `lists_named` | `names` (список) | у каждого раздела из `names` есть хотя бы один пункт | `{missing}` — названия без пунктов | нет |
| `min_items` | `list`, `min` | в разделе `list` пунктов не меньше `min` | `{n}`, `{min}` | `too_few_items` |
| `max_items` | `list`, `max` | в разделе `list` пунктов не больше `max` | `{n}`, `{max}` | нет |
| `min_lines` | `min` | непустых строк в файле не меньше `min` | `{n}`, `{min}` | нет |
| `contains_text` | `text`, `match` или `loose` (необязательно) | в файле есть строка `text` | — | `text_missing` |
| `forbidden_text` | `text`, `match` или `loose` (необязательно) | в файле нет строки `text` | — | нет |
| `no_placeholder` | — | в файле нет заготовок (см. ниже) | `{n}` — сколько найдено | `placeholder_left` |
| `answer` | `label`, `expect` (одно слово) или `answers` (список) | значение после метки `label` допустимо во всех строках с этой меткой | — | `answer_mismatch` |

Код причины уходит на сайт вместо текста. Его берут из файла `<имя правил>.reasons.txt` рядом с правилами (строки `id=код`, код — `^[a-z0-9_]{1,40}$`). Если для невыполненного правила там кода нет, у типов с кодом по умолчанию используется он; у остальных кода нет. На сайт уходит код первого невыполненного правила, строгость которого равна вердикту (у `disputed` — первого невыполненного правила со строгостью `disputed`); если у него кода нет, отметка уходит без причины. Поэтому порядок правил в файле значим: сначала правила `failed`, потом `disputed`, потом `almost`, и у каждого правила код той же строгости. Так плагин и сайт одинаково понимают «спорно»: сайт решает, ждёт ли шаг куратора, по строгости кода.

### Поиск текста: `match` и `loose`

`contains_text` и `forbidden_text` ищут `text` как подстроку. Поле `match` меняет сравнение:

- `exact` (по умолчанию) — точное, регистр различается;
- `nocase` — без учёта регистра;
- `nospace` — без учёта пробелов, табуляций и переводов строки (значение, записанное в строку и в столбик, находится одинаково);
- `nocase_nospace` — оба.

`"loose": true` — то же, что `"match": "nocase_nospace"`; `"loose": false` ничего не меняет. `loose` и `match` вместе — ошибка в правиле. Текст, который после сведения оказывается пустым, — тоже ошибка.

Без учёта регистра сводятся латинские буквы, русские А–Я и Ё, украинские Є, І, Ї, Ґ. Остальные буквы сравниваются как есть. Метка порядка байтов в начале файла и `\r` в конце строк в текст не входят.

### Разделы и пункты

Раздел задаётся одним из способов:

- заголовок `#`…`######` с пробелом после решёток, любого уровня (закрывающие решётки `## Название ##` отбрасываются);
- строка-метка у левого края: `Порядок:`, `**Порядок:**`, `**Порядок**:`, `**Порядок**`;
- строка-метка с текстом после двоеточия (`**Порядок:** текст`) — но только если название есть в правилах (в `heading`, `list` или `names`), чтобы обычные фразы с двоеточием не делили файл на разделы.

Названия сравниваются так: убираются `*` и `_` (выделение), номер в начале (`1.`, `2)` с пробелом после), двоеточия и точки в конце, лишние пробелы; регистр не учитывается. Поэтому `## 1. Порядок:`, `**ПОРЯДОК**` и `Порядок` — одно название.

Пункты раздела — строки, начинающиеся с маркера (`-`, `*`, `+`) или номера (`1.`, `1)`, до трёх цифр) и пробела или табуляции, после которых есть текст. Пункты относятся к ближайшему выше заголовку или метке. Не считаются: пустые пункты (`-`, `- `), горизонтальные черты (`---`, `* * *`) и вложенные пункты (с отступом больше, чем у первого пункта списка; отступ больше трёх пробелов, табуляция считается четырьмя, не начинает список). Абзац у левого края заканчивает список.

Область подсчёта. Если среди правил есть `has_heading` и его заголовок найден в файле как заголовок (не как метка), пункты считаются только внутри блока этого заголовка: до следующего заголовка того же или более высокого уровня. Область задаёт первое такое правило. Чтобы правило `has_heading` только проверяло наличие раздела и не сужало область, добавьте в него `"scope": "none"`.

### Заготовки: `no_placeholder`

Заготовка — место для ответа, оставленное из шаблона: `<` + текст + `>` на одной строке. Текст между скобками должен:

- быть длиной от 1 до 80 знаков;
- содержать хотя бы одну букву (латиницу или кириллицу): `<да или нет>`, `<ваш ответ>`, `<123 слов>` — заготовки, `<123>`, `<...>`, `<?>` — нет;
- не начинаться и не кончаться пробелом, табуляцией, `-` или `=`.

Заготовкой не считаются:

- HTML-комментарии `<!-- … -->` (в том числе на нескольких строках; незакрытый комментарий идёт до конца файла);
- HTML-теги из списка: `a abbr b blockquote br caption center code col dd del details dfn div dl dt em figcaption figure font h1`–`h6` `hr i img ins kbd li mark ol p pre q s samp small span strike strong sub summary sup table tbody td tfoot th thead tr tt u ul var`, открывающие, закрывающие и с атрибутами (`<br>`, `<br/>`, `</details>`, `<a href=x>`); имя тега без учёта регистра;
- адреса и почта: текст со схемой (`https://…`, `ftp://…`), `mailto:…`, `имя@домен` без пробелов;
- знаки сравнения и стрелки: `<=`, `>=`, `<-`, `->`, `=>`, а также `<` и `>` с пробелами вокруг слов и чисел (`a < b и c > d`).

Слово вне списка тегов, например `<your name>` или `<span2>`, заготовкой считается. Если внутри скобок встретилась ещё одна `<`, поиск начинается с неё (`<а <б> в>` — одна заготовка `<б>`).

### Ответ в строке: `answer`

Правило ищет все строки, в которых перед первым двоеточием стоит метка `label` (сравнение как у названий разделов; строка может быть пунктом списка и содержать выделение). Значение после двоеточия приводится к виду: без `*` и `_`, без пробелов по краям, с одним пробелом между словами, без учёта регистра. Значение допустимо, если оно равно разрешённому слову (`expect` или одному из `answers`, приведённых так же) или начинается с него, а дальше (после пробелов) идёт конец строки либо один из знаков `,` `-` `–` `—` `.` `:` `;` `!` `(` `[` и любой комментарий.

Допустимы: «да», «Да.», «да, удалил», «нет — это проба», «Нет (проба)». Недопустимы: «данет», «да нет наверное», «да конечно» (слово без знака после), «не знаю», пустое значение, заготовка. Правило выполнено, если такая строка есть и допустима **каждая** строка с этой меткой. Нужно задать ровно одно из `expect` и `answers`.

### Файлы: `path`

`file_absent` и `file_exists` с `path` проверяют, есть ли что-то по пути внутри учебной папки. Путь проверяется так же строго, как `file`; если на пути к файлу стоит ссылка, программа завершается с кодом 2.

## Правила версии 3

Файл правил с `"version": 3` читает программа проверки уровня 3 (плагин 0.3.0); плагин 0.2.0 говорит на таком шаге «обновите плагин». Версия выше 3 — тоже «обновите плагин». Файлы версий 1 и 2 считаются как раньше.

**Строгий формат.** Правило версии 3 — один JSON-объект на одной строке. Неизвестный тип, лишнее или недостающее поле, значение не по таблице, повтор `id`, больше 40 правил — код выхода 2 и ни одной строки вывода. Значения: строка в двойных кавычках (до 200 знаков, непустая, без управляющих знаков и обратной косой черты), целое от 0 до 99999, `true` или `false`, список из 1–16 разных строк, число вида `61` или `1234.5` (без знака и порядка, до 9 цифр, до 4 после точки), хеш из 64 знаков `0-9a-f`.

**Новые типы** (общие поля `id`, `type`, `on_fail`, `ok`, `fail`; подстановок `{…}` у них нет):

| Тип | Поля | Выполнено, если | Код причины по умолчанию |
|---|---|---|---|
| `file_unchanged` | `path`, `sha256` | по `path` обычный файл не больше 256 КиБ, и sha256 его байтов (без преобразований строк и кодировки) равен `sha256` | `file_changed` |
| `contains_number` | `value`, `tolerance` (по умолчанию 0), `list` | в тексте (с `list` — под этой меткой) есть число, отличающееся от `value` не больше чем на `tolerance` | `number_missing` |
| `contains_some` | `texts`, `min`, `loose` | из строк `texts` найдено не меньше `min` разных (`min` от 1 до числа строк) | `too_few_matches` |
| `each_item_has` | `list`, `any`, `loose` | под меткой `list` есть пункты, и в каждом пункте есть хотя бы одна строка из `any` (регистр не важен всегда) | `item_without_mark` |
| `fields_filled` | `labels` | для каждой метки есть строки «метка: значение», и во всех значение заполнено (не пусто, не одни прочерки и точки, без заготовки) | `field_empty` |

Число в тексте ищется проходом по знакам каждой строки: цифры, группы по три цифры через пробел, неразрывный пробел U+00A0, U+2009 или U+202F (`1 234 567`), десятичная часть после точки или запятой. Число не считается, если оно часть слова или номера (перед ним буква, цифра, `-`, `_`, `/`, после него буква или цифра). Числа сравниваются целыми в десятитысячных долях. Отрицательные числа и запись `1,234.50` не поддержаны.

**Поле `path`.** У каждого правила по тексту (`has_heading`, `lists_named`, `min_items`, `max_items`, `min_lines`, `forbidden_text`, `contains_text`, `no_placeholder`, `answer`, `contains_number`, `contains_some`, `each_item_has`, `fields_filled`) может быть `path`: правило читает этот файл учебной папки, а не главный. Путь — от одного до четырёх сегментов из `A-Za-z0-9._-`, до 120 знаков, без `..`, сегмент не `.`, не кончается точкой и не имя устройства Windows. Путь вне учебной папки или не по этим правилам — код выхода 2. Файл читается только внутри учебной папки: ссылка (символическая ссылка, соединение папок) на файле или на любой папке пути не читается, правило не выполнено. Правило с `path` не пропускается, когда главного файла нет; если файла по `path` нет, правило по тексту не выполнено, а `forbidden_text` выполнено.

**Пределы чтения.** Файл больше 262144 байт не читается, правила по нему не выполнены. Файл со знаком NUL текстом не считается: правила по тексту не выполнены (`file_unchanged` NUL не важен). Текст читается как UTF-8, метка порядка байтов снимается, CRLF и одиночный CR становятся LF.

**Что в версии 3 считается иначе, чем в версии 2.** `has_heading` видит только заголовок `#`, не метку. Пунктами раздела считается каждая строка-пункт под меткой, с любым отступом (в версии 2 — только пункты верхнего уровня). Метка раздела с двоеточием — строка, которая им кончается. Заготовка в `no_placeholder` — любой `<…>` на одной строке длиной от 1 до 200 знаков, кроме текста с `@` или `://` внутри и текста, у которого сразу после `<` стоит `!`, `=`, `-`, пробел или табуляция (поэтому `<123>`, `<b>` и `<...>` — заготовки, а `<a@b>` и `<=` — нет).

**Коды по умолчанию** — те же правила, что выше: код из файла `<имя правил>.reasons.txt`, а если для правила строки нет, код по типу правила (таблица типов и таблица новых типов).

## Пакет задания (`stratum-task 1`)

Команда `/course:next` берёт задание одним запросом, `POST <сайт>/api/plugin/task` с заголовком `Authorization: Bearer <токен>` и телом `{"plugin_version":"0.3.0","os":"windows|mac|linux","engine":3}` (`engine` — уровень правил, который понимает программа проверки). Человека определяет только токен: какой шаг текущий, решает сайт. Ответ — текст UTF-8, переводы строк LF, без метки порядка байтов, не больше 262144 байт (плагин больше не читает):

```text
stratum-task 1
state=step
module=m1
step=s2
module_title=<название модуля>
step_title=<название шага>
number=2
of=5
file=notes/report.md
check_version=3
min_engine=3
waiting=0
boundary=<32 знака 0-9a-f>

--<boundary> task
<текст шага>
--<boundary> rules
<файл правил шага>
--<boundary> reasons
<файл кодов причин шага>
--<boundary> start notes/example.md
<содержимое стартового файла>
--<boundary> end
```

- Первая строка — ровно `stratum-task 1`. Другая цифра — плагин говорит «обновите плагин». Всё остальное, что не по формату, плагин отвергает целиком и ничего не пишет на диск.
- Шапка — строки `ключ=значение` до первой пустой строки; ключи `[a-z_]+`, значение без управляющих знаков (C0, C1, U+2028, U+2029, знаки нулевой ширины и направления текста) и не длиннее 300 байт; повтор ключа — ошибка, неизвестные ключи пропускаются. `state` — `step` (есть текущий шаг) или `done` (шагов не осталось, частей нет, сразу строка `end`; `waiting` — сколько шагов ждут куратора). При `state=step` обязательны `module`, `step` (до 10 знаков `a-z0-9`), `module_title`, `step_title`, `number`, `of`, `file` (главный файл шага, совпадает с полем `file` правил), `check_version`, `min_engine` (равно `check_version`, 1–99), `waiting`, `boundary`. Необязательный `story_path` — путь страницы модуля на сайте (плагин печатает ссылку при первом показе шага).
- Часть начинается строкой `--<boundary> <вид>`; виды `task`, `rules`, `reasons` — ровно по одной, `start <путь>` — от нуля до восьми, `end` — последняя строка пакета. Строка, начинающаяся с границы, но не являющаяся верной строкой части, — ошибка. Содержимое части — строки до следующей границы, каждая кончается LF; в пакете нет NUL и CR, пакет кончается LF.
- Если `min_engine` больше уровня программы проверки (сейчас 3), плагин не записывает ничего и говорит «обновите плагин».

Что плагин делает дальше: сохраняет пакет в папке данных плагина; если задание на этой машине ещё не показывалось или главного файла нет — кладёт недостающие стартовые файлы в учебную папку и показывает задание (только вместе с показом: перед проверкой ничего не восстанавливается); иначе проверяет работу по сохранённым правилам и отправляет отметку (`passed` и код причины, как в разделе про код причины). При «принято» запрашивает следующее задание. На сайт по-прежнему уходит только вердикт и код причины.
